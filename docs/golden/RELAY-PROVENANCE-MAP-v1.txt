# StorageRelayProvenanceMap v1 golden row vector

**Status:** deterministic storage-layout vector for T-pass verification; not a v3.1 wire-protocol vector.

## Fixture

- ScopeId UTF-8: `relay-provenance-sample`
- LocalReplica: `A1 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00`
- NamespaceId: 7
- Original author: same NodeId as LocalReplica
- JournalSeq: 1
- ChangeId: .NET Guid `10000000-0000-0000-0000-000000000001`, represented by `Guid.ToByteArray()`
- OutboxSeq: 1
- Cursor: ScannedThroughJournalSeq=3, AckedThroughOutboxSeq=0, AckedThroughJournalSeq=0

All hex is byte-for-byte, no separators.

- Mapping value (24 bytes; little-endian JournalSeq=1 followed by ChangeId):  
  `010000000000000000000010000000000000000000000001`

## Required assertions

1. Cursor and mapping keys share the same 49-byte root.
2. Cursor kind is `01`; mapping kind is `02`.
3. NamespaceId is little-endian u16.
4. OutboxSeq is big-endian u64 in the mapping key, so prefix-cursor order is destination sequence order.
5. JournalSeq is little-endian u64 in the mapping value; ChangeId is exactly 16 bytes.
6. Cursor marker is ASCII `RPM1`, followed by three little-endian u64 values.
7. No OriginSequence, payload, fingerprint or peer-specific ACK is stored in this mapping row.

T-pass must compare these bytes against actual persisted rows produced by the sample and reject any mismatch.
