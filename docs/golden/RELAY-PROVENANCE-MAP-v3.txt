**Status:** deterministic storage-layout vector for T-pass verification; not a v3.1 wire-protocol vector.

## Fixture

- ScopeId UTF-8: `relay-provenance-sample`
- LocalReplica: `A1 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00`
- NamespaceId: 7
- Original author: same NodeId as LocalReplica
- Pre-resolved sequence pairs (ChangeId resolution is held in BIN-SYNC's global ChangeId ledger and is deliberately not duplicated here):
  - JournalSeq=1 → OutboxSeq=1
  - JournalSeq=1 → OutboxSeq=2
  - JournalSeq=2 → OutboxSeq=3
- Cursor: ScannedThroughJournalSeq=3, AckedThroughOutboxSeq=0, AckedThroughJournalSeq=0

## Required assertions

1. Cursor and mapping keys share the same 49-byte root.
2. Cursor kind is `01`; mapping kind is `02`.
3. NamespaceId is little-endian u16.
4. OutboxSeq is big-endian u64 in the mapping key, so prefix-cursor order is destination sequence order.
5. Mapping value is only little-endian JournalSeq[8]. ChangeId is not copied into this table: the caller must resolve each FLD ChangeId through BIN-SYNC's durable global ChangeId ledger before calling `AppendPage`.
6. Cursor marker is ASCII `RPM3`, followed by scanned JournalSeq, ACKed OutboxSeq, ACKed JournalSeq (little-endian u64 each), then the 32-byte mapping-set digest.
7. Mapping-set digest is the XOR of SHA-256(`key || value`) for every retained mapping row. Append and prune update rows and digest in the same Storage write batch; restart recomputes it from bounded prefix pages and compares in constant time.
8. No ChangeId, OriginSequence, payload, fingerprint or peer-specific ACK is duplicated in a mapping row.

T-pass must compare these bytes against actual persisted rows produced by the sample and reject any mismatch.
